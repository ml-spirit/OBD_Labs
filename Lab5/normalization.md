Організація баз даних
Лабораторна робота 5: Нормалізація бази даних  
Тема: Аналіз функціональних залежностей та нормалізація схеми бази даних "Electronic Cupboard".

1. Аналіз функціональних залежностей  

Ми проаналізували основні таблиці нашої схеми (source, cupboard, shelf, cell, object) на предмет надлишковості даних та аномалій.

Таблиця source  
Первинний ключ: source_id  
ФЗ: source_id → name, description, link, picture, manufacture  
Аналіз: Поле manufacture містило текстове значення виробника, яке повторювалося у багатьох записах. Це призводило до надлишковості даних та можливих аномалій оновлення.  

Рішення: створено окрему таблицю manufacturer та додано зовнішній ключ manufacturer_id у таблицю source.

Таблиця cupboard  
Первинний ключ: cupboard_id  
ФЗ: cupboard_id → name, description, access, location  
Аналіз: Поле access зберігалося у вигляді тексту, що призводило до дублювання значень. Також поле shelf_id обмежувало одну шафу лише однією полицею, що не відповідає предметній області.  

Рішення: створено таблицю access, додано access_id та видалено shelf_id.

Таблиця shelf  
Первинний ключ: shelf_id  
ФЗ: shelf_id → name, size, access  
Аналіз: Поле access дублювало значення доступу, а поле cell_id обмежувало одну полицю однією коміркою.  

Рішення: створено зв’язок shelf → cupboard через cupboard_id, винесено access у окрему таблицю, видалено cell_id.

Таблиця cell  
Первинний ключ: cell_id  
ФЗ: cell_id → name, size, color  
Аналіз: Відсутній зв’язок з полицею, що ускладнює структуру зберігання.  

Рішення: додано зовнішній ключ shelf_id для зв’язку з таблицею shelf.

Таблиця object  
Первинний ключ: object_id  
ФЗ: object_id → source_id, name, description, count, weight, size  
Аналіз: Відсутній зв’язок із місцем зберігання об’єкта.  

Рішення: додано зовнішній ключ cell_id для прив’язки об’єкта до комірки.

2. Перевірка нормальних форм  

Перша нормальна форма (1NF)  
Вимога: атомарність атрибутів, відсутність повторюваних груп.  

Статус: Виконується.  
Обґрунтування: усі поля містять атомарні значення, списки або масиви не використовуються.

Друга нормальна форма (2NF)  
Вимога: відсутність часткових залежностей.  

Статус: Виконується.  
Обґрунтування: у таблицях використовуються прості первинні ключі, тому залежності від частини ключа відсутні.

Третя нормальна форма (3NF)  
Вимога: відсутність транзитивних залежностей.  

Проблеми:  
- дублювання виробників у полі manufacture  
- дублювання значень доступу у полі access  
- некоректні зв’язки між таблицями  

Рішення:  
- створено таблицю manufacturer  
- створено таблицю access  
- змінено структуру зв’язків: cupboard → shelf → cell → object  

---

3. Результат нормалізації  

Після нормалізації структура бази даних має вигляд:

manufacturer → source  
access → cupboard  
access → shelf  
cupboard → shelf  
shelf → cell  
cell → object  
source → object  

Це дозволило усунути дублювання даних, виправити логіку зв’язків та привести базу даних до третьої нормальної форми.
